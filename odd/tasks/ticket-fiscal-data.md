# ticket-fiscal-data

## Objective
Make the 80 mm ticket (sale and credit note) carry the fiscal data of the botica set in Ajustes: razón social, RUC, dirección fiscal, plus the amount in words ("SON: ... SOLES"). QR and hash stay a backend duty and are documented, not faked.

## Constraints
- Contract first (CLAUDE.md): `docs/API.md` -> `types.ts` -> `contract.ts`/`http.ts` -> mock (`mock/client.ts`, bump `VERSION`) -> pure rules with tests -> screens -> README/BACKEND docs.
- No new dependencies. UI text in Peruvian Spanish. Never write a botica name in code.
- Money: `round2`, soles with 2 decimals. Do not change any amount or rule.
- Old data without the new fields must still print (fallback to `name` and to the branch address).
- No Co-Authored-By. Conventional commits. One work-unit commit per phase. No push or merge without the user.
- Checks: `npm run typecheck`, `npm test`. TDD: not configured; pure helpers get Vitest tests. Runner: Vitest.
